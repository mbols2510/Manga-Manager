# Manga Manager 3.3.2

Result of checking the Kavita calls against a real server (Kavita 0.9.1.4).

## Changed

- **Marking a chapter read** now uses `POST /api/Reader/mark-multiple-read` with
  `{"seriesId": ..., "volumeIds": [], "chapterIds": [<id>]}` (both `KavitaClient.mark_chapter_read`
  and the Double Chapters tool). The old `POST /api/reader/mark-chapter-read` still works on
  Kavita 0.9.1.4, but it is not in the current Kavita source (`main`), so it may disappear.
  `mark-multiple-read` was tested on 0.9.1.4: a partly read chapter became fully read.

## Verified against a real server

- Token accepted, admin account, version 0.9.1.4.
- `GET /api/Series/volumes`, `POST /api/Series/all-v2`, `GET /api/Server/is-task-running`
  (JSON `true`/`false`, `true` seen during a scan); `/api/Server/activity` is 404 (handled).
- `POST /api/Reader/progress` sets the page and caps a too-high `pageNum` at the page count.
- Cover upload: `POST /api/Upload/upload-by-file` is 404 on 0.9.1.4, so the app's base64 fallback is used.
  `POST /api/Upload/series` with `{id, url: <base64>, lockCover: true}` returns 200 and the cover is served as PNG.
- `POST /api/Series/scan` accepts both `{libraryId, seriesId, forceUpdate}` and `{seriesId}`.

## Not tested

`POST /api/Library/scan`, upload-by-file on a Kavita that has it, and the API-key login (`/api/Plugin/authenticate`).
