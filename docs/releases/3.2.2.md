# Manga Manager 3.2.2

Released 9 November 2026. Corrects the unusable bulk preview and image-request
queues reported after 3.2.1.

## Bulk preview and folder mapping

- Fixed a namespace collision: Compose's `MANGA_ROOT` is a host path, while
  Double Chapters needs the mounted container path. It now uses `DC_MANGA_ROOT`
  (default `/manga`), and the Compose file explicitly sets the container path.
- Recovers the exact legacy saved host-path collision when the saved path is
  unavailable and the standard `/manga` directory exists. Valid custom folders
  keep their existing precedence. Path boundaries, traversal and outside-folder
  protections remain in place.
- Replaced the plain keep/trash text list with the existing chapter-card layout:
  selected radio cards, file names/folders, dates, sizes, page counts, and the
  Official / Newest / Largest badges.
- Added **Official, else newest / Newest / Largest** selection buttons and
  individual selectable file cards. Apply validates and honors the reviewed
  selections. Signed/expiring previews and stale-file checks still apply.
- Groups skipped chapters into compact expandable warnings with folder-mapping
  guidance, instead of filling the dialog with repeated messages.

## Image loading and request load

- Updates and Doubles now share a viewport-aware cover loader with a maximum of
  two concurrent cover downloads per page, with bounded retries for failures.
- Doubles retains existing image elements when its list refreshes and no longer
  repeatedly rebuilds the cover grid.
- Added a disk cache for proxied Kavita covers, private browser caching, ETags,
  stale-cache fallback when Kavita is offline, and a limit of two concurrent
  uncached Kavita image fetches. Cover fetch timeouts are shorter.
- Missing Updates thumbnails have bounded generation/fetch concurrency. Requests
  for the same thumbnail no longer race while writing its cache file.
- Removed duplicate bulk-status requests and two-second idle polling. Doubles
  uses one serial status request every 15 seconds when idle and every two seconds
  during scanning/processing, and pauses polling while the page is hidden.

## Verification

Regression tests cover the host/container environment conflict, legacy saved-path
recovery, directory-prefix safety, reviewed custom choices, invalid selections,
cover caching/conditional responses, and nonblocking upstream concurrency limits.

An isolated Chromium test with 122 duplicate chapters verified enabled Apply,
card selections, all three strategies, cancellation, stale-preview rejection,
custom-choice application and Trash records. With deliberately delayed images,
both tabs stayed at a maximum of two simultaneous cover requests; the initial
viewport loaded 12 of 122 Doubles covers and eight thumbnails for 60 Updates
entries. These are sample-data measurements, not a live-server benchmark.

## Upgrade

Use `ghcr.io/mbols2510/manga-manager:3.2.2` (Linux amd64/arm64), or the `latest`
channel. Reuse your existing database, configuration and mounted folders. No
destructive database migration is required.

With the default mount, the tool's container folder should be `/manga`. For a
custom mount, set **Settings → Double chapters → Manga folder in this container**
and, if needed, **Manga folder as Kavita sees it** to the matching container paths.

After updating the container, reopen the web app to load its new scripts. This
publishes the correction; it does not run a server deployment or process live
library files automatically.
