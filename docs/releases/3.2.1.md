# Manga Manager 3.2.1

Released 9 November 2026.

This release restores the 3.1.0 server baseline, replaces the Android companion
with an installable web interface, and adds a reviewed, library-wide duplicate
chapter cleanup action.

## Changes, in implementation order

### 1. Restore 3.1.0 and retire the Android companion

- Restored the exact `v3.1.0` source tree before adding the changes below. This
  removes the Android project, build/release workflows, pairing/device-token UI,
  bearer-token authentication and Android `/api/v1` changes/device endpoints
  introduced after 3.1.0. The normal web login and existing 3.1.0 tools remain.
- Removed the `android-v0.1.0` release, its APK/checksum downloads, and its tag.
- Preserved Git history and the historical server releases/tags (`v3.0.0`,
  `v3.1.0`, `v3.2.0`). The 3.2.0 tag remains an archive of that earlier release.

### 2. Clean repository branches

- Deleted the retired Android feature/spec branches and both existing Dependabot
  branches. Only `main` remains.
- Removed the temporary repository-cleanup workflow after verifying its result.

### 3. Installable web app (PWA)

- Added a web app manifest, maskable 192/512-pixel icons, an Apple touch icon,
  standalone display mode, and an **Install app** button in supporting browsers.
- Added a service worker and a clear offline/reconnect screen. Only public shell
  assets are cached. Login/account pages, manga covers and API responses are not
  stored by the worker; processing still requires a live server connection.
- Supports the existing web session and reverse-proxy URL prefixes. No APK,
  pairing, mobile token, or extra service is needed.

To install at `https://manga-manager.tech-bol.be`, use **Install app** or the browser
menu in Chrome/Edge/Android. On iPhone/iPad, use Safari **Share → Add to Home
Screen**. Sign in with your existing account. HTTPS is required on real devices;
plain HTTP LAN addresses do not provide normal PWA installation/service workers.

### 4. Preview and process all manga with duplicate chapters

- Added **Process all manga…** to Doubles. It covers every manga in the latest
  duplicate scan, including series outside the open chapter window.
- The preview shows manga/chapter totals, every keep/trash choice, disk usage,
  skipped chapters, and the configured trash-retention period. Expanding a manga
  reveals its chapter details. Opening, closing or refreshing it moves nothing.
- Uses the existing defaults: **official, otherwise newest**; among multiple
  official files the newest official wins. The bulk action does not inherit a
  temporary manual "Largest" selection from another window.
- Requires an explicit **Apply choices** action. The signed preview expires in
  15 minutes and is checked again before processing. Changed files, scan results
  or folder settings require a fresh preview.
- Runs on the server in the background with progress, per-chapter failures and
  Kavita-refresh warnings. Reloading the browser reconnects to current progress.
- Skips unavailable, unsafe or shared file paths; never removes alternatives
  when the chosen file to keep is missing. Successful moves remain recorded in
  Trash even if a later move in the chapter fails.
- Prevents overlapping scans/batches and conflicting Double Chapters writes;
  uses Move Manga's existing exclusive file-operation lock. Rescans Kavita once
  per affected manga and runs the existing read-status reconciliation.

Files moved by this action can be restored through **Trash**, subject to your
existing retention setting and any later permanent deletion. If the server
restarts during a batch, rescan and make a fresh preview; the batch does not
automatically resume. Progress is held in the running server process.

## Upgrade

The Docker image is `ghcr.io/mbols2510/manga-manager:3.2.1`, for Linux amd64 and
arm64. Existing configuration, mounted folders and PostgreSQL data are reused.
Back up your database, `/config` and `/data` before upgrading. No destructive
database migration or automatic chapter cleanup is part of this release.
Unused Android-era database fields/tables may remain inert in an existing 3.2.0
database; the restored server does not expose or use the Android API.

For an explicitly pinned deployment, set the Compose image to the tag above,
then run these commands on your server when you choose to upgrade:

```sh
docker compose pull manga-manager
docker compose up -d manga-manager
```

The existing `:latest` and `:main` channels continue to be published. After
upgrading, reopen or refresh the site to obtain the current service worker.
This task publishes the release and images; it does not deploy to the Ubuntu
server or process any production chapters.

## Verification

- Linux/PostgreSQL CI runs the full Python regression suite and builds/runs the
  Docker image's version command before release publication.
- New automated coverage checks defaults, preview expiry/signatures, login and
  cross-site protections, stale/missing/shared paths, overlapping operations,
  partial failures, and public PWA assets including URL-prefix behavior.
- Isolated Chromium checks cover a mobile preview, cancellation without moves,
  stale-preview rejection, apply/progress/reload, the service-worker cache,
  offline navigation and reconnection. These use disposable local sample files.

Actual installation on iOS/Android devices and the live Ubuntu deployment have
not been exercised as part of this release.
