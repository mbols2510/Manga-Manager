# Manga Manager 3.3.1

Released 14 November 2026. Security and safety fixes from the review of the
9 November commits (`docs/reviews/2026-11-09-review.md`, findings M1, M3 and M4).

## Bulk duplicate cleanup

- **Admin only (M3).** Bulk preview, bulk apply and per-chapter remediation now
  require an administrator (a `config.yml` account or the first account), like
  Settings. Accounts created through the sign-up page can no longer move files
  to the Trash.
- **Never keeps a bad copy (M1).** A chapter is skipped, and listed as needing
  review, when the file that would be kept is empty, or (for a non-official
  file chosen by date) is less than half the size of, or has fewer pages than,
  another copy. Official files are still preferred, but an empty one is never
  kept. Previously a truncated newest file could win and the complete copy was
  trashed, then deleted for good after the retention period.
- **Final confirmation (M1).** Apply now asks for confirmation, stating the number
  of files and chapters, their total size and when the Trash is emptied.

## Publishing (M4)

- Images are only built after the tests pass (`ci.yml` is reused by
  `docker-publish.yml`), so a failing commit no longer overwrites `:latest` and `:main`.
- A release is only published when its tag equals the application version
  (`v3.3.1` for `__version__ = "3.3.1"`).

## Not changed

The other findings of the review (long file lock during Kavita polling, cover
cache growth, service worker caching, line endings) are not part of this release.
Trash retention is unchanged (7 days by default).

## Upgrade

Use `ghcr.io/mbols2510/manga-manager:3.3.1` (Linux amd64/arm64), or the `latest`
channel. No database migration. If you use bulk cleanup, preview it again: some
chapters may now appear under "needs attention".
