## Medium

**M1. Auto-selected "keep" file can destroy the good copy.**
`tools/double_bulk.py:50-53` (keep rule), `tools/double_chapters.py:399-400` (sort), commits 252a42d / c2484e0.
Default keep rule is "official, else newest mtime". A truncated, corrupt or 0-byte newest file wins by mtime, the
larger complete file goes to Trash, and `purge_expired_trash` deletes it permanently after
`dc.trash_retention_days` (default 7). Apply covers every chapter in one click; the "Largest" button can trash an
official file. `chapter_plan` checks only that files exist and are inside the root.
Fix: flag a chapter as "needs review" when the chosen keep file has `bytes == 0` or noticeably fewer `pages`/`bytes`
than a trashed sibling; show these in the preview; add a final confirm with total count and size; consider longer
retention or no auto-purge for bulk-created trash.

**M2. Bulk processing holds the shared file-operation lock for a very long time.**
`double_bulk.py:164` (`scheduler.run_exclusive(self._process)`), `:209`, `double_chapters.py:~600`
(`reconcile_read_status`). `_process` blocks Move Manga for the whole run; after each series it polls Kavita up to
10 times at 1.5 s per chapter. With hundreds of chapters this can take tens of minutes and defers all Suwayomi downloads.
Fix: release the exclusive lock after the file moves; run the rescan/reconcile outside `run_exclusive`; cap total reconcile time.

**M3. Bulk apply is not admin-gated.**
`web.py` `ADMIN_ENDPOINTS` (line 28) lacks `double_chapters.bulk_*` and `remediate`. With `auth_allow_signup` on,
self-created accounts can trash files across the library. Precedent exists in `can_edit_aliases`.
Fix: add `double_chapters.bulk_preview`, `double_chapters.bulk_apply`, `double_chapters.remediate` to `ADMIN_ENDPOINTS`.

**M4. CI does not gate image publishing; no tag/version check.**
`.github/workflows/docker-publish.yml:6-9` and `ci.yml`. Publishing triggers on every push to main in parallel with CI
(no `needs`, no tests), so a failing commit still overwrites `:latest` and `:main`. On `release: published`, semver
tags come from the git tag with no check against `__version__`. The deleted temporary 3.2.1/3.2.2 publishers did both
checks; that logic was not carried into the permanent workflow.
Fix: gate on CI (`workflow_call` or `workflow_run`); on release events assert `github.event.release.tag_name == "v" + __version__`.

## Low

- **L1. Service worker cache** (`templates/service-worker.js:3,21`, `web.py` `service_worker`): cache name is
  `manga-manager-shell-<__version__>-1`; `app.css`, `tools.css`, `pwa.js` are cache-first. A CSS fix without a version
  bump never reaches installed PWAs. Fix: stale-while-revalidate, or a content-hash cache id.
- **L2. Service worker never caches private data (verified)**, with two gaps: a 502/503 from a down proxy shows the
  proxy page instead of the offline page (treat status >= 500 on navigation as offline); `cache.addAll` fails the whole
  install if any asset 404s.
- **L3. Unbounded cover cache** (`image_cache.py:23-60`): nothing deletes files; the key includes the Kavita URL and API
  key so rotation orphans files; `/cover/<int:series_id>` accepts any integer (placeholder-200 fill risk is unverified).
  Fix: max-files/bytes LRU sweep; key on series id plus URL only.
- **L4. Cover errors and image safety**: non-image 200 body raises `ValueError` not caught by `cover()` (500 instead of
  502, `double_chapters.py:~800-807`); `image/svg+xml` passes the `image/` check with no CSP; covers lack `no-store`.
  No SSRF or path traversal (admin-controlled host, int id, sha256 filenames). Fix: allowlist image types, catch `ValueError`.
- **L5. Cover loader hides covers permanently after transient 503s** (`static/image_loader.js:19-22`,
  `static/double_chapters.js:83-90`). Fix: do not hide on final failure; retry on next `refreshSeries` or focus.
- **L6. Full stat sweep under `tool.lock`** (`double_bulk.py:73-75`, `:117-121`). Fix: sweep outside the lock; re-verify only the fingerprint inside.
- **L7. Partial failure leaves stored state out of sync** (`double_chapters.py:~486-496`, `remediate_chapter`): `series`
  saved only at the end. Self-heals after a rescan. Fix: save in a `finally`.
- **L8. Trash filename dedupe mangles names** (`double_chapters.py:499`, pre-dates the reviewed changes).
- **L9. Dependabot and workflow-lint dropped with Android** (`debecdf`). Re-add the `github-actions` update block if wanted;
  actions are pinned by major tag, not SHA.
- **L10. Orphan `device_tokens` table** on deployments that ran 3.2.0. Optional one-time `DROP TABLE IF EXISTS device_tokens`.
- **L11. Stale comment and non-idempotent release step**: `docker-publish.yml:4-5` still says "release v3.1.0"; the deleted
  temporary publishers ran `gh release create` last, so a retry could push images twice. No temporary workflows remain.

## What looks good

The preview-token, fingerprint and per-chapter re-verification design is careful; every destructive step re-checks live
state with `is_safe_path` before any move. The service worker is conservative (tiny public allow-list, network-only pages
and APIs, `no-store` on the SW and HTML). The cover proxy has no SSRF/traversal exposure and is concurrency-bounded.
The Android removal cleanly drops every server-side artifact.
